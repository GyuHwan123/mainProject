# PicToText 팀 소개용 설명 스크립트

안녕하세요. 이번 프로젝트는 OCR 기반 문서 처리 서비스를 제공하는 PicToText 웹 애플리케이션입니다.

저희는 Frontend, Backend, Database, OCR, Auth 영역을 함께 구성하면서, 빠르게 기능을 검증하고 실제 서비스 흐름까지 염두에 두고 개발하고 있습니다.

현재 구조는 React + Vite 기반의 프론트엔드와 FastAPI 기반의 백엔드로 나뉘어 있습니다. 프론트에서는 로그인, 대시보드, OCR 화면, 리포트 화면, 마이페이지를 구성하고 있으며, 백엔드에서는 사용자 인증, JWT 발급, API 라우팅, DB 연결을 처리하고 있습니다.

특히 인증 파트에서는 이메일/비밀번호 로그인과 소셜 로그인 준비 구조를 함께 구성해 두었습니다. 사용자가 회원가입하거나 로그인하면 서버가 사용자 정보를 검증하고, 내부 JWT를 발급해서 대시보드로 이동하도록 연결되어 있습니다.

데이터베이스는 로컬 개발 단계에서는 SQLite로 검증하고 있고, 이후 Supabase 또는 PostgreSQL 환경으로 확장할 수 있는 구조로 설계되어 있습니다. 사용자 테이블을 기준으로 이메일, 이름, 비밀번호 해시, provider, created_at 등 정보를 관리하고 있습니다.

현재 소셜 로그인은 Supabase OAuth를 기반으로 준비되어 있습니다. 프론트엔드에서 버튼 클릭 시 Supabase 세션을 받게 되고, 그 세션 access token을 서버로 전달해 내부 JWT를 다시 발급하는 방식입니다. 이렇게 하면 외부 제공자 토큰을 그대로 노출하지 않고, 우리 앱의 인증 규칙을 일관되게 유지할 수 있습니다.

또한 보안상 중요한 포인트가 있습니다. Supabase의 `service_role key`는 관리자 권한 키라서 절대로 프론트엔드에 넣으면 안 됩니다. 공개 가능한 값은 `anon key` 정도만 프론트에 두고, 서버만 비밀 값들을 관리하도록 설계하고 있습니다.

OCR 기능은 아직 다음 단계로 진행 중입니다. 현재 구조는 서버 쪽에서 PaddleOCR를 붙일 수 있도록 준비가 되어 있고, 향후 업로드된 이미지 파일을 받아 텍스트를 추출해서 결과를 보여주는 흐름을 붙일 예정입니다.

프로젝트의 핵심 목표는 간단합니다. 사용자가 문서를 업로드하면 텍스트를 추출하고, 보고서로 정리하고, 필요하면 이후 AI 해석까지 이어지는 구조를 만드는 것입니다.

지금까지는 핵심 흐름이 연결된 상태입니다. 로그인, 회원가입, 인증, 보호 페이지, DB 저장, JWT 발급까지는 검증이 되었고, 다음으로는 PaddleOCR 연동과 실제 문서 처리 흐름을 연결해 나가고 있습니다.

이 프로젝트는 로컬 검증용으로는 빠르게 동작하게 만들고, 이후 Docker나 Supabase 환경으로 안전하게 전환할 수 있도록 설계되어 있다는 점이 장점입니다. 그래서 팀원 간 협업이 쉬우며, 기능 단위로 테스트와 확장이 가능합니다.

앞으로는 OCR 처리, 결과 저장, 소셜 로그인 실연동, Supabase PostgreSQL 전환까지 이어서 진행할 예정입니다. 이 단계가 끝나면 사용자에게 실제로 쓸 수 있는 문서 인식 서비스 형태로 완성될 수 있습니다.

감사합니다.
